### Defeitos

1. **Média — Opções dinâmicas podem deslocar o executável e produzir falsa ausência.** Em `timeout "$OPCAO" TERM 30s npm run personal:watch`, `OPCAO=--signal` torna a chamada válida. O parser olha apenas para `TERM`, trata a expansão como duração e perde o `npm`. Em `timeout --signal=$OPCAO npm run personal:watch`, `OPCAO='TERM 30s'` também permite executar o `npm`, mas o parser rejeita `npm` como duração. Nos dois cenários, `alertas-logs` deveria ficar parcial. [audit-readiness.mjs](/home/app/projects/agent-control/deploy/modules/prontidao/audit-readiness.mjs:1848)

2. **Média — `"$@"` pode desaparecer mesmo entre aspas.** Em `timeout -- "$@" 30s df -P /`, uma execução do script sem argumentos chega ao `df`. O parser presume que `"$@"` ocupa uma palavra, toma `30s` como executável e deixa `disco-memoria` com cobertura completa e achado de ausência. [audit-readiness.mjs](/home/app/projects/agent-control/deploy/modules/prontidao/audit-readiness.mjs:1715)

3. **Média — Um wrapper incerto consome o limite de shells aninhados.** Em `timeout -- 1,5s sh -c 'sh -c "df -P /"'`, a chamada recursiva feita para interpretar o `timeout` incrementa a profundidade. O segundo `sh -c` fica fora do limite e o coletor perde a evidência possível de disco. O mesmo ocorre com `npm run personal:watch` no shell interno. [audit-readiness.mjs](/home/app/projects/agent-control/deploy/modules/prontidao/audit-readiness.mjs:2165)

4. **Média — A filtragem de consultas descarta operações reais de backup.** Em `timeout -- 1,5s pg_dump -h db.example app`, `-h` informa o host. Em `timeout -- 1,5s sh -c 'pg_dump db' --help | cat`, `--help` vira `$0` do shell. A busca por essas palavras em qualquer argumento elimina os dois candidatos e permite publicar `PRONTIDAO-BACKUP-AUSENTE` onde a cobertura deveria ser parcial. [audit-readiness.mjs](/home/app/projects/agent-control/deploy/modules/prontidao/audit-readiness.mjs:2144)

5. **Média — A incerteza de locale é confundida com incerteza sobre a posição do executável.** Em `timeout 1,5s 30s npm run personal:watch`, se a duração for aceita, o executável indicado é `30s`. O parser considera que `1,5s` pode ocupar a posição de uma opção e procura candidatos mais adiante, marcando `alertas-logs` como parcial por causa de um `npm` que só aparece entre os argumentos. [audit-readiness.mjs](/home/app/projects/agent-control/deploy/modules/prontidao/audit-readiness.mjs:1927)

6. **Média — Uma duração hexadecimal negativa é aceita como zero.** Em `timeout -- -0x0d npm run personal:watch`, o `d` é o último dígito hexadecimal de −13. O classificador o remove como sufixo de dias, encontra um mantissa zero e aceita o comando como evidência de alertas. [audit-readiness.mjs](/home/app/projects/agent-control/deploy/modules/prontidao/audit-readiness.mjs:1698)

7. **Média — Uma listagem comum passa a degradar a cobertura de backup.** Em `timeout -- 1,5s sh -c 'find . -print'`, o ramo novo marca `backup-restauracao` como parcial porque aceita qualquer `find` como candidato. O comando apenas lista caminhos e, mesmo se executado, não satisfaz a regra de retenção do coletor. [audit-readiness.mjs](/home/app/projects/agent-control/deploy/modules/prontidao/audit-readiness.mjs:2146)
