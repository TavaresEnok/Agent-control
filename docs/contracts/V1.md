# Contratos v1 e ingressos

Schemas executáveis: `src/contracts.ts`. Principal é derivado do autenticador, nunca de `principal_id` enviado no payload. O launcher sintético verifica o bearer no servidor real Happier.

`Command` distingue intentId e deliveryAttemptId. Contexto, ação, versão e payload formam o digest; trocar somente a entrega não altera a intenção. Conflito semântico é 409. O ID nativo de mensagem Happier é convertido deterministicamente em UUID por contexto; texto não precisa de `[op:...]`. O banco armazena referência/hash e outbox cifrada, não o texto.

`Authority` usa contextId, instanceId e epoch. Aquisição usa transação e clock do PG; instância concorrente recebe MANAGER_ACTIVE. Reinício do mesmo perfil recebe epoch nova. Novas admissões e spawn da fixture exigem época vigente; pausa não é removida por takeover.

`Checkpoint` conserva referências de objetivo, restrições, decisões, plano, artefatos, pendências e cursor. O endpoint novo lê checkpoint e até 150 mensagens cifradas da sessão vinculada, decifrando em memória. Paginação histórica completa e política de seleção são pendências I2.

`Projection` tem eventId, contextId, runId, planRevision, seq, status. Unique(run_id,seq) deduplica a persistência. O estado publicado vem do RunStore; o adaptador não decide o próximo nó. Ordenação/cursor completo em todos os clientes é pendência.

## Superfícies habilitadas

- Happier RPC/fila nativos -> mesmo `Ledger.accept`, autenticado pelo servidor, sessão vinculada e principal conferido.
- `POST /api/v1/ac/commands` -> mesmo `Ledger.accept`; schema estrito recusa principal forjado.
- Contexto/pausa/leitura -> RBAC no PG. Criar vínculo por API falha fechado sem verificador de propriedade da sessão.
- `GET /api/v1/runs/:uuid[/events|history|diff]` -> acesso por contexto antes de delegar ao Cezar.
- Links de conversa por run -> sessão canônica autorizada.

## Superfícies recusadas

POST/PUT/DELETE nativos Cezar, aliases de projeto, MCP, automação, terminais, upgrades WS e rotas não inventariadas. A aplicação nativa Cezar fica embutida, sem listener separado que permita contornar o gateway. As demais ações de administração ainda precisam de contratos e testes antes de serem habilitadas.

Estados físicos supported nesta fatia: registered, running, completed, uncertain. Uma operação incerta sem run reconhecível é recusada; não existe recuperação automática de processo arbitrário nesta entrega. A operação sintética só executa o script fixo inspecionado, com ambiente reduzido, dentro do container de laboratório. Isso não demonstra isolamento hostil entre workers.

O bootstrap de leitura do cockpit (`health`, projeto, configuração, workflows e metadados autorizados) exige associação ao projeto do runtime. IDs de escopo estrangeiros recusam; o alias `default` aponta somente para o runtime corrente. A lista de runs é filtrada por associação PG; permissões não são inferidas de um ID enviado pelo navegador. Escritas nativas, atualização de drafts/config e controles não implementados continuam recusados, inclusive quando a UI upstream ainda os consulta. A conclusão da administração visual é I6.

A recepção da pending queue e o relay de intenções já confirmadas não compartilham uma falha fatal: erro de consulta/ack mantém aquela entrega pendente e auditada, mas não suspende a execução autorizada e a publicação de recibos já persistidos. O RunManager continua sendo o único decisor do grafo.
