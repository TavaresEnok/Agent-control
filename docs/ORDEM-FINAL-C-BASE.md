Relatório privado rastreável em <dataDirectory>/verificacoes/ com prova, cobertura e falhas; achados devem ser convertíveis em tarefas do produto de forma idempotente, com ligação ao projeto, critério de aceite e caminho real de correção. Não inclua a conclusão dos autores nos pedidos de revisão.

O coletor inicia pelo ENTRYPOINT da imagem com /repo montado somente leitura, raiz read-only, usuário sem privilégio, /tmp gravável, sem socket, sem login real e rede desligada por padrão. Pode copiar os arquivos necessários em /tmp para execução isolada. A saída stdout é um único JSON UTF-8 com {coverage:[{tool,version,status,detail}],findings:[{tool,rule,file,line,severity,message,evidence}]}. status é ok, failed ou skipped, severity é alta, media, baixa ou informativa, line é inteiro >=1, file é caminho relativo do repositório. Falha de ferramenta fica na cobertura e faz a CLI sair com erro depois de gravar o relatório. Toda ferramenta deve informar o que realmente conseguiu medir. Guarde detalhes de cobertura por arquivo, rota ou requisito como linhas adicionais. O gerente fará o build, registrará o ID Docker imutável em deploy/modules/<modulo>/digest.txt e executará os laboratórios no host antes da integração final. Para o laboratório use AC_MODULE_LAB=1 e imagem pelo digest. Não invente digests, notas, versões ou resultados.
