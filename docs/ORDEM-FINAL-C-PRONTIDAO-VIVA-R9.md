### Defeitos de medição

1. **Média · R7, duração inválida vira evidência.** Em `timeout 30S npm run personal:watch`, o `/i` da nova regex aceita o sufixo maiúsculo. O GNU `timeout` rejeita `S` antes de iniciar o `npm`, mas o coletor pode contar o comando como evidência de alertas. Em `timeout 30ss npm run personal:watch`, o novo teste de prefixo numérico faz outro literal inválido virar ambiguidade, podendo suprimir `PRONTIDAO-ALERTA-AUSENTE` e gerar uma falha de cobertura indevida. A mesma validação afeta `--kill-after`. [audit-readiness.mjs](/home/app/projects/agent-control/deploy/modules/prontidao/audit-readiness.mjs:1677) · [GNU Coreutils](https://github.com/coreutils/coreutils/blob/v9.7/src/timeout.c#L294-L344)
2. **Média · R7, a posição do executável pode continuar indeterminada.** Em `timeout "$OPCAO" 30s npm run personal:watch`, se `OPCAO=--foreground`, o executável é `npm`. O diff consome `"$OPCAO"` como duração e marca a posição como conhecida. A reavaliação começa em `30s`, perde o `npm` e pode publicar `alertas-logs` como `ok` com um achado de ausência. Antes, a busca por posições possíveis chegava ao `npm`. A correção para argumentos de `printf` é válida quando a análise consegue fixar a posição do executável. [audit-readiness.mjs](/home/app/projects/agent-control/deploy/modules/prontidao/audit-readiness.mjs:1902)
3. **Média · R7, normalização de sinais ainda incompleta.** `timeout --signal=271 30s npm run personal:watch` continua produzindo cobertura parcial, embora o GNU normalize `271` para `15` (`TERM`). O diff resolve `143`, mas ainda classifica como dinâmico um literal com interpretação determinada no GNU.
