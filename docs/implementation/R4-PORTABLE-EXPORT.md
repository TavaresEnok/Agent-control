# Portable redacted metadata v2

This delivery addresses truncation and missing contracts in metadata portability. It does not create a restorable backup, duplicate conversation storage, export global account custody, or authorize any execution. Existing v1 metadata API and `PortableExport.export()` remain unchanged.

The versioned GET `/api/v1/ac/contexts/:contextId/export/metadata/v2` creates a durable redacted cut for the authenticated project owner. Subsequent GET requests carry the returned `cursor`. Each response is at most256KiB; its base64 payload is a maximum160KiB fragment of one section's canonical JSON array. A single logical record may span pages without dropping fields. The manifest declares each section's record count, byte length and SHA256; pages carry chunk and envelope digests. The HMAC cursor binds export ID, principal, project, context, section and exact byte offset using a random per-cut database key. Current owner membership is checked again on every page. No key is returned.

The snapshot is assembled in one serializable database transaction, then retained in083's immutable header/section rows. Concurrent insertions and mutable integration updates cannot change an existing cut. Serializable/timeout conflicts require a new retry, rather than publishing a partial snapshot. Explicit refusal applies beyond32MiB canonical metadata,10000source records in any section, or4active cuts per principal. There is no implicit100record truncation. Access expires after24hours. New cuts opportunistically delete up to100expired cuts and all expired cuts belonging to the caller; `purgeExpired()` is also available to maintenance. Physical deletion at an exact wall-clock deadline is not promised without a caller. DELETE of the exact v2 export ID releases only the authenticated principal/project/context's cut. The CLI always attempts that release after collecting its temporary cut, including failure paths. Cleanup cannot grant a revoked owner access.

The collected DTO includes complete capacity role chains and ordered regular/emergency profile UUID references; complete manager task fields/dependencies/correction/parallelism contracts; frozen workflow definitions and manager compilations with full structure; artifact identity/provenance; typed verification receipts when recognized and explicitly opaque redacted JSON for legacy receipts; waivers, integration, approvals and every context audit row at the cut. No global account or credential configuration is copied.

Sensitive text is represented by explicit digest tokens: content references, branch/path scopes, names, prompts, commands, URLs, secret references, arbitrary unknown text and dynamic JSON property names. Workflow schema-owned field names and finite structural enums remain readable; opaque source/edge references preserve equality through tokens. Unknown receipt/audit JSON preserves its shape and numeric/boolean data with keys and strings hashed. Quality protected paths are similarly tokenized. This DTO preserves metadata structure and relationship evidence, not plaintext task instructions or executable definitions. It is explicitly `restorable:false` and `conversationIncluded:false`. Source digests identify original records; separate page/section/envelope digests authenticate the redacted exported bytes. They are never claimed to be the same digest.

`collectPortableMetadata()` reconstructs and verifies every fragment and section, then returns a complete v2 envelope. `exportContext()` now includes this complete metadata in an explicitly versioned `agent_control_context_export_v2` file. Its existing canonical Happier message pagination, ciphertext fields, sequence checks, private output custody and bounded message count/size remain unchanged. It continues to export encrypted canonical history without decryption or keys. The overall32MiB context-file limit remains an explicit refusal.

Validation uses only newly created random child databases in the author's labeled disposable PostgreSQL16. The focused v2 test includes more than100audit rows, a single plan larger than256KiB after redaction, full ordered fallback chains, all64task scopes/ref fields, frozen definition and source evidence digests, concurrent post-cut insertion, service replacement with durable cursor, forged/cross-context/cross-project/revoked/released/expired cursors, bounded expiry purge, active-cut cap, cross-context deletion refusal, whole-section cap refusal, and known text canaries. The old v1 test is also rerun. These are metadata/controller fixtures; no provider, physical worker, real account, deployment or operational migration is claimed.
