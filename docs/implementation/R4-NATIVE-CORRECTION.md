# Native correction contract v4 — review before QA

T21 literally requires a reproducible QA defect after implementation and initial review, then correction with new evidence. The earlier bounded native recipe v2 ran QA before review, so a QA rejection skipped that initial review. The manager authorized a narrow change for newly compiled native correction plans. No architectural ADR found in this checkout overrides that literal ordering; ordinary zero-correction and synthetic workflows retain their previous behavior.

New native correction admissions emit ManagedRecipe4 with description `native-correction-review-before-qa-v1`. Every attempt runs implementation → independent review → QA → selection/integration, with optional judge as already required by policy. Failed review or QA still opens at most the frozen correction bound. New corrected artifacts must obtain new review and QA evidence; commit/tree identity, failed-evidence references, scopes and task identity remain fenced by the existing correction protocol. Native composition in these new recipes uses the same review-before-QA order.

Historical ManagedRecipe1/2/3 remain parseable and their stored frozen graphs/digests are never rewritten or recompiled. Synthetic correction2 and specialist3 builders keep their existing ordering. Dynamic workflow names stay `engineering-native-plan-<uuid>` so exact frozen snapshot resolution remains compatible. Recipe4 is native-only; unsupported future versions are rejected. The exported `supportsManagedRecipeContract(raw)` reflects the actual loaded package's parser. The rollover author additionally validates the real target package's ManagedRecipe parser, recipe digest, parent and frozen workflow digest; WorkflowDef parsing alone cannot approve recipe4 for an old package.
