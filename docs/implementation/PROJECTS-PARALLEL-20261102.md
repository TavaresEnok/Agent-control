# Projetos — entrega paralela 2026-11-02

A configuração privada de versão 1 aceita `project` como antes e, opcionalmente, `projects` como lista de objetos com os mesmos campos. `initialize` valida raízes Git canônicas, aplica as migrações existentes e registra projetos, dono e caminhos em PostgreSQL, de forma transacional; somente o dono de `project` recebe automaticamente administração global. Não existe rota HTTP para registrar projetos ou diretórios. A migração 037 adiciona `ac_project_repositories`; caminhos são incluídos apenas na projeção nativa de projetos autorizados.

`GET /api/v1/ac/projects` retorna `{projects:[{id,label,role}],selectedProjectId}` somente para o principal autenticado. `X-Agent-Control-Project` seleciona UUID e `/api/v1/p/:uuid/...` seleciona UUID sem cabeçalho; com ambos, devem coincidir. `default` representa o projeto inicial. A associação em PostgreSQL é conferida para cada solicitação antes de iniciar ou escolher runtime. O runtime padrão é carregado no início; os demais são criados sob demanda, no máximo quatro por processo, sem descarte automático. Cada runtime mantém um cliente do pool de oito por sua vida. A inicialização ocorre fora de transação e concorrências para o mesmo projeto compartilham uma promessa; um quinto projeto recebe 503. A ocupação por outros processos e o banco ainda dependem de capacidade própria.

O gateway encaminha `workspace/events` após ACL por projeto; o handler seguro no gateway central deve interceptar antes da delegação nativa, pois o SSE nativo pode sondar credenciais. Rotas nativas de status de provedores/modelos também são bloqueadas pelo gateway existente. `CEZ_HOME` aponta para `dataDirectory/cezar`; variáveis de telemetria, automações e atualização de skills são desativadas. `CEZ_DRY_RUN` não é evidência suficiente de ausência de todas as sondagens; a superfície nativa restante precisa de auditoria independente.

`GET /api/v1/projects` projeta o registro PG no contrato nativo, com root restrito por ACL, `projectsDir` vazio e datas de registro persistidas. A disponibilidade Git é revalidada ao consultar; `lastOpenedAt` representa a data de registro, pois abertura não é rastreada. Pendências para integração: Verificar no gateway central a associação de todo recurso, contexto e run ao runtime escolhido, inclusive comandos e aliases nativos, e completar testes de ponta a ponta da UI antes de declarar isolamento multi-projeto. A lista, os testes de fábrica e a configuração não estabelecem isolamento completo da UI. A disponibilidade do SSE depende da integração do handler seguro central; não há endpoint de escrita ou gestão de ACL.

Validação: `docker compose -f deploy/compose.lab.yml exec -T runtime node --import tsx --test tests/installation.test.ts tests/projects.test.ts` passou 3/3 em banco criado e eliminado pela fixture; nenhum projeto real foi registrado. `npm run typecheck` executado no workspace. Não houve migração de banco operacional, inferência, publicação ou acesso a contas reais.
