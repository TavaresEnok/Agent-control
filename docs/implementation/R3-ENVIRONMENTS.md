# R3 — project environments (079, work in progress; not accepted)

This checkpoint preserves the current RF-01/RF-02 implementation before the user-requested stop. It is not a claim that the full feature was integrated or accepted.

`ProjectEnvironments` publishes signed owner-only immutable revisions with CAS and semantic intent/delivery replay. The configuration identifies a source Git branch and up to eight environments with unique target branches, existing repository-relative authorized subdirectories, and local-repository or registered remote-host destinations. The registered repository must be beneath a configured trusted startup root. Repository/.git identity and each authorized directory's device/inode are captured and rechecked before new effects. Paths reject traversal, symlinks, `.git` and `.ai`. This slice deliberately supports existing tracked subdirectories, not repository-root files such as `package.json` or `README`.

The exact global API factory is `createProjectEnvironmentApi(new ProjectEnvironments(ledger, projectRoots, privateDirectory))`, returning `(request, principal) => Promise<Response>`. It handles `GET /api/v1/ac/project-admin/environments?projectId=<uuid>` and signed JSON POST to the same exact path. The caller must authenticate the session and validate browser Origin first. The body is capped at 16 KiB with a ten-second read deadline. GET returns current revision/config/canConfigure and sanitized remote-host IDs/labels/allowed purposes, never roots, credentials, fingerprints or filesystem identities. Existing ProjectAdmin signer identity supplies installation/device IDs.

The signed action is `project.environments.configure`, with payload `{projectId, expectedRevision, config:{sourceBranch,environments}}`. A local destination is `{id,label,kind:'local_repository'}`; remote is `{id,label,kind:'remote',hostId,allowedPurposes:['remote-development','remote-return']}`. Remote development requires the existing host `git-workspace` task; return requires `git-return`. Existing delivery task/workspace policy remains the remote path authority. Environment authorization separately pins host fingerprint and immutable registration digest and requires exact project/purpose/target, rejecting ambiguous selection when no target is supplied.

Migration 079 adds separate environment bindings keyed to the unchanged execution-contract digest. Contract INSERT pins environment/revision and checks frozen write paths. Grant admission and new local integration intents require the current binding and authorized destination/target. Publication refuses active grants, unsettled execution contracts, or prepared/uncertain integrations. This prevents silently replacing an accepted live contract. Existing terminal journals can still be read/reconciled; new effects using stale bindings are refused. Legacy projects with no configuration retain their earlier admission behavior. PostgreSQL trigger refusals map only a closed set of codes to public 403 responses.

Programmer native/isolated launch, supervised local composition and preparation of a new local integration call `requireProjectEnvironmentLaunch` before their effect journal. The first programmer/parent-plan launch resolves the configured source branch's current real Git commit and freezes it in an immutable parent source record. Later legitimate batches can consume a registered composition of that parent: the helper validates frozen input/recipe digests, completed operation receipt, artifact commit/tree/base, immutable composition source snapshots, exact registered source artifacts and bounded composition lineage to the original source. Selected correction units must map to the frozen logical task through the immutable task-selection record and digest. An arbitrary descendant or changed branch tip is insufficient. The old source pin does not move when a branch advances.
