# Identidade do processo finalizador — 05/11/2026

`ac_native_artifact_finalizations.process_handle` identifica um grupo de processos local. Antes desta alteração, ausência de um PGID no namespace atual ou diferença de boot era tratada como prova de ausência do grupo original. Isso não é suficiente para concluir que um processo em outro namespace ou host deixou de escrever. O supervisor agora grava também o identificador do namespace PID e só considera o grupo ausente quando boot e namespace são os mesmos e a consulta local confirma ausência. Um handle legado sem namespace, ou de outro namespace/boot, permanece incerto; o cancelamento não envia sinal a um PID homônimo nem libera concessão por essa observação.

Handles antigos já finalizados continuam legíveis; handles antigos ainda não resolvidos ficam bloqueados, inclusive após reinicialização ou troca de namespace. Esta é uma contenção, não um protocolo de reconciliação entre hosts: resta implementar e revisar uma prova de parada originada na autoridade física correta. Não alterar dados existentes para presumir o namespace. A identificação por namespace e boot também não é uma prova geral contra comprometimento do host.
