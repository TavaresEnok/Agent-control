## Efeito Git em andamento

Um segundo caso lança o Ruby sem congelamento anterior à entrada e observa seu filho `git add --all` com o lock do índice e um objeto temporário Git de tamanho positivo. A fixture congela o grupo nesse ponto, confirma ambos os processos parados e mata o controlador com SIGKILL. O supervisor mantém a concessão ocupada; a época antiga é rejeitada; outro processo cancela e só libera após comprovar ausência do grupo. A prova observa escrita já iniciada em objeto temporário, não conclusão do commit nem retomada do grafo; os contêineres continuam simulados. Os sete casos da suíte passaram no banco isolado; o caso com objeto temporário foi repetido após reforçar a observação física.

Duas primeiras tentativas do caso novo falharam: a fixture tentou inserir um handle que o finalizador real já havia inserido e, depois, observou `git add` antes de existir o lock. As correções usam o handle real e aguardam lock e objeto temporário com conteúdo. Essas falhas não são contadas como aprovação. A identidade de início do órfão agora é capturada antes das asserções, permitindo limpeza segura se uma delas falhar.
