# R3 — bounded durable reconciliation history

Migration 071 adds stable, immutable membership sequence numbers for intents, semantic planning calls, sandbox, native execution, native QA and remote operations. Existing rows are backfilled once. Source INSERT/UPDATE triggers reactivate existing per-lane visits and increment row revisions; timestamps and UUID order are never progress cursors.

Each invocation processes at most 32 membership candidates per lane. A sweep freezes its ceiling, so later arrivals cannot extend that sweep. Progress records the numeric cursor, preceding ceiling, sweep number, CAS revision and authority epoch. Page acknowledgement uses the ledger authority fence even while paused. A successor inherits progress; a crash before acknowledgement replays the page. Physical reconciliation must remain idempotent; the history mechanism does not replace physical identity/receipt validation.

Normal sweeps merge indexed active visits with fresh membership beyond the preceding ceiling. Each SQL branch is independently limited before merging; a partial active index avoids searching all inactive history. Every sixteenth sweep audits the full membership in bounded pages, including rows whose eligibility changed only through related tables and sequence holes published behind an earlier cursor. Visits are independent per lane. Source modifications racing acknowledgement remain active through revision comparison.

Under a finite membership bound N and successful bounded invocations, a sweep completes in at most ceil(N/32)+1 calls; an unchanged uncertain row is revisited within two such sweeps, and an inactive dependency-only change or late sequence hole within at most seventeen sweeps. This is a call-count bound, not a time guarantee: database/network/physical reconciliation latency and unavailable authority can delay progress. Continuous arrivals cannot extend an already frozen sweep; no fixed global latency is promised under unbounded arrivals.

Cezar wires integration cancellation, terminal sandbox children, planning, native execution, cancellation state, sandbox cancellation, native QA and remote cancellation to durable pages. Independent job/phase errors remain aggregated after later work runs. Cancellation state uses a savepoint per request, allowing later successful requests to commit despite one callback/SQL failure. Completed sandbox children and physically confirmed sandbox stops leave the active set; eligibility failures and uncertainty stay active. Other terminal jobs leave the set when their existing eligibility query no longer selects them.

## Evidence and limits

Only the disposable PostgreSQL 16 container `ac-r3-history`, labelled `ac.lab=disposable`, was used by this author. No operational migrations/accounts/providers were accessed.

- Node 22.23.3, `node --import tsx --test tests/r3-history.test.ts`: three tests passed, zero skips. PostgreSQL migrations, persisted replay/CAS, old authority rejection, uncertainty revisits, old source modifications, acknowledgement races, independent lanes, dependency audit, finite arrivals, failure progress and real cancellation row isolation were exercised.
- The sequence-hole case explicitly allocates a sequence value then inserts a registry fixture behind progress. It models late visibility; it does not claim an actual uncommitted source INSERT crossed the fence. PostgreSQL source FK locks would block that fence in the attempted direct fixture.
- The crash case recreates the helper after persisting an idempotent SQL effect and dropping acknowledgement. It proves durable at-least-once replay, not OS SIGKILL of a physical executor.
- `EXPLAIN (ANALYZE, BUFFERS)` with 20,000 memberships and 19,999 inactive visits returned one candidate using indexed scans, with 7–8 shared blocks in author/reviewer runs. This is a finite plan observation, not an absolute CPU/I/O bound. Periodic audit and one-time migration/backfill still scale with retained history; history storage has no retention policy.
- Independent reviewer `/root/r3_review_runtime` found that an unqualified outer `ORDER BY seq` sorted the text projection lexicographically on a fresh sequence crossing 9/10. The query now explicitly orders numeric `candidates.seq`; reviewer independently reran all three tests successfully in a separate fresh PostgreSQL container.

The existing QA physical backlog fixture now polls finite ticks and checks the first tick stays within 32; orchestration-only Cezar mocks explicitly stub history and do not claim paging coverage. Focused regressions: `tests/cancellation.test.ts` plus `tests/r2-graph-cancellations.test.ts` passed five tests, zero skips; `tests/r2-qa-retirement-physical.test.ts` passed its real Docker test, including both functional outcomes and the 40-job bounded backlog. `npm run typecheck` passed with normal compiler settings. Build prerequisites use local dependency/dist links; these are untracked environment artifacts and not part of the patch.
