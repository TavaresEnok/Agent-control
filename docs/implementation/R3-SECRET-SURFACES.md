# R3 — RNF-08: auditoria finita de superfícies de segredo

Checkpoint de encerramento solicitado pelo usuário. Nenhum segredo real, conta real, provedor ou inferência foi utilizado. Não se encontrou defeito novo de sanitização no caminho gerenciado examinado; não foi alterado módulo de produto. A prova focada `tests/r3-secret-surfaces.test.ts` passou 1/1, zero skips, em aproximadamente cinco segundos. Este é resultado do autor; a revisão independente desta extensão permanece pendente e não se declara aceite integral de RNF-08.

## Caminhos inspecionados e prova

O teste executa um subprocesso Node 22.23.3 com ambiente allowlist (HOME/PATH/locale/TZ, URL PostgreSQL exclusivamente descartável e canário sintético). Recusa variáveis de credenciais reais comuns. Gera chaves/canários novos de host, registro por run, formato de PAT, transporte, capability de tools, chave de contexto e master de vault. Não enumera ou imprime credenciais do ambiente externo.

Usa PostgreSQL filho UUID, CezarRuntime/RunStore reais e APIs do produto sem iniciar execução. Registra o run admitido com o placeholder gerenciado `Intent <UUID>`. Introduz canários em evento profundamente aninhado de stdout/stderr/Authorization, delta dividido em dois fragmentos, evento efêmero, título derivado e erros de run/step. Confere ausência dos valores literais e bytes de chave/master em NDJSON, runs.json, eventos em memória, frame SSE do produto, GETs autenticados de runs/run/history e histórico reaberto do disco após fechar o runtime. O redator existente é o responsável pela sanitização; a prova não inventa um redator alternativo. A primeira tentativa de GET interno recebeu 403 por ausência de Host, conforme a guarda nativa: a requisição final identifica explicitamente `Host: 127.0.0.1`, sem desabilitar a proteção.

Os caminhos HTTP de logs brutos, vault/master e segredos de workspace são recusados pelo gateway gerenciado. Um erro de autenticação contendo canários vira somente INTERNAL_ERROR; mensagem privada não é retornada. Insere uma linha legada hostil explicitamente sintética em ac_audit.detail para verificar que PortableExport e o download real de metadata fazem projeção whitelist e não copiam aquele payload. Isso não afirma que o banco legado foi limpo: a linha privada continua privada, e não é produção de novo segredo pelo produto.

O exportador de conversa lê token privado de arquivo 0600 e o usa no Authorization de uma origem HTTP autenticada de fixture. Exporta ciphertext real da biblioteca Happier, mantendo bytes/ordem, `keysIncluded: false` e sem texto de usuário em claro, token de transporte, chave ou master. O vault real autentica/cifra a chave sintética e permanece fora do repositório. O token de tools vai no campo de controle executionEnvironment do adaptador real, enquanto systemPrompt/userPrompt contêm apenas tarefa e escopo; erro privado do runner de fixture é transformado em código EXECUTION_NATIVE_TURN_FAILED. O runner é somente captura de fronteira, sem CLI, inferência ou execução física.

Um commit e bundle Git reais, contendo somente o arquivo admitido src/safe.ts, não incluem vault, tokens, chaves ou histórico untracked. Esse check é restrito ao bundle de fonte deste teste; não substitui a prova física R3-FLOW de isolamento/HOME e varredura de 121 arquivos. A persistência/restauração HTTP Happier real e o rewrap já provados em R3-MIGRATION são reutilizados como evidência anterior, sem repetir o fluxo completo. O HTTP deste teste é fixture de transporte do exportador, não nova prova de servidor Happier real.

## Reprodução e limites

```sh
AC_TEST_DATABASE_URL=postgresql://postgres:synthetic-r3-migration@127.0.0.1:32785/ac_implementation_test PATH=/tmp/node-v22.23.3-linux-x64/bin:$PATH node --import tsx --test tests/r3-secret-surfaces.test.ts
```

A URL do comando era exclusivamente a bancada nova desta frente, removida no encerramento; para reproduzir é preciso outro PostgreSQL descartável com banco base ac_implementation_test. O teste cria/remove apenas seu banco UUID e diretórios próprios. O arquivo de evidência resume o resultado observado pela ferramenta, não se apresenta como log stdout bruto. O typecheck local identificou conflito preexistente de union ProfileExclusion em diagnostic-projections.ts/contrato de diagnóstico; foi informado ao integrador. Nenhum erro de tipo nos novos arquivos foi reportado nesse check, mas não se declara typecheck geral verde desta worktree.

A auditoria leu os wrappers nativos gerenciados que publicam texto fixo com commit/status em vez de logs brutos e a whitelist de metadata. Os logs nativos brutos continuam custódia privada fora do repositório; esta prova não os reclassifica como exportáveis. O redator trata valores conhecidos/registrados e formatos reconhecidos, não promete detectar qualquer segredo desconhecido ou transformado. Um usuário que coloca segredo no próprio prompt exige política específica; o transcript deve preservar sua cifra e não pode ser declarado removido em todas as cópias por esta prova. Campos de continuidade genéricos do Cezar upstream e sessões nativas fora do gateway gerenciado não são abrangidos. Sem varredura universal de todos os ataques, sem alteração operacional, sem broad flow adicional e sem promoção a aceite sem revisão independente.
