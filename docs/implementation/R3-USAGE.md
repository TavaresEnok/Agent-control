# R3 — RF-40 usage report and paginated CSV

The authenticated product API now serves `GET /api/v1/ac/contexts/:contextId/usage/report` and `/usage/report.csv`. Both require UTC `from`/`to`, a positive window of at most 93 days whose comparison start is after 1970. Optional filters are `profileId`, `rework=all|only|exclude`, `limit=1..200`, and `cursor`. Context membership and the selected runtime project are checked before either the current or prior period is read. Still-open model grants are retained as unknown attempts even without a counter observation or stage timestamp; absence of collection cannot turn those attempts into a complete zero. Historical released attempts lacking both terminal timing and in-window observations remain outside the observation-window scope. Model-backed grants only are included; local compositor reservations do not become provider usage.

Counter attribution follows server observation timestamps, not an inference activity clock; delayed collection can shift reported deltas across windows. The current period is `[from,to)`; the comparison period immediately precedes it with the same duration. Per-attempt token counters are differences between the latest cumulative observation before the end and the latest before the start. An attempt created in the window has an initial zero baseline. An older attempt missing its starting baseline, a missing field, or an invalid regression produces unknown, not a fabricated zero. Duplicate adapter events remain deduplicated by the existing usage ledger. Input, output, cache and reasoning stay separate because they may overlap.

Each profile/rework comparison includes attempt counts and, per counter, the known subtotal, known/unknown attempt counts and a complete total only when all included attempts are known. Deltas compare complete totals only. The arithmetic is exact decimal integer strings, avoiding JavaScript precision loss. These are reported adapter counters, not independently measured subscription consumption. Subscription balance and monetary cost remain unknown; no prices, statistical quality comparisons or performance conclusions are invented.

Time is separately sourced from completed server stage lifecycle records linked by the exact grant. Exactly one stage row, a completed state and a finite monotonic started/finished pair are required. Its wall interval is clipped to each period and expressed as integer milliseconds. A running stage, missing timestamps or ambiguous multiple stages produces unknown. Stage intervals also participate in report membership, so an old stage without a new counter observation is not silently omitted. This is lifecycle wall time including reconciliation delays; active model/inference time always remains unknown. Time comparisons carry their own known/unknown counts and conservative deltas.

Rework means an immutable `ac_managed_correction_decisions.next_intent_id` relation for the grant's intent in the same context. An unlinked attempt is labelled as having no recorded correction, not proof that it involved no other form of retry. Profile model/effort metadata is explicitly current; the schema does not contain a historical profile snapshot.

Each request uses one repeatable-read transaction for the page and complete filtered-period summaries. SQL statements have a ten-second timeout; cancellation returns `USAGE_REPORT_TIMEOUT`/503, never partial successful data. Pagination preserves PostgreSQL timestamp precision and binds the cursor to project, context, window and filters. Each request has its own snapshot: concurrent updates may change later pages and their summaries. No multi-request immutable export snapshot is claimed.

CSV exports exactly one bounded page, identified by `usage-page-<context>.csv`, `X-Usage-Export-Scope: page`, `X-Usage-Page-Complete` and optional `X-Next-Cursor`. Each row also contains page metadata. A client collecting a complete export must follow all cursors and report any interruption. All fields are quoted, quotes doubled, and spreadsheet formula prefixes (including leading whitespace/control characters) neutralized. Responses are private `no-store` downloads with MIME sniffing disabled. No operator signature is needed for this read-only report.

Migration 077 adds period/grant indexes. It was applied only to the author's disposable `ac-r3-usage` PostgreSQL 16 container, labelled `ac.lab=disposable`.

## Validation and independent review

Node 22.23.3: `node --import tsx --test tests/r3-usage-report.test.ts` passed one integrated test, zero skips, against real disposable PostgreSQL and the real central `createApi` authentication/error boundary. The fixture covered exact period boundaries, cumulative delta versus snapshots, duplicate observations, unknown baselines/fields, recorded correction linkage, current profile metadata, known lifecycle clipping, ambiguity/running unknowns, full-period summaries on every page, microsecond keyset pagination, profile/rework filters, cursor filter mismatch, bounded/invalid contracts, spreadsheet formula escaping, unauthenticated/foreign membership and runtime-project rejection. It uses synthetic stored observations and stage records, not live provider collection or physical inference. `npm run typecheck` passed with normal compiler settings.

Independent product reviewer `/root/r3_review_product` reran the focused integrated test in a separate disposable PostgreSQL instance and approved the scoped implementation. Review identified the initially missing time metric; the final implementation includes lifecycle wall time and explicit active-model unknowns. Evidence remains partial for RF-40: no live provider collector, historical profile revisions, immutable multi-page export snapshot, currency pricing or advanced analytics is claimed.
