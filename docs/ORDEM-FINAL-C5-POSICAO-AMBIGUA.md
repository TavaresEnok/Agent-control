# Origem conservadora em blocos e pilhas de execução SQL

A revisão de 94af07b4 mostrou que pertencer ao mesmo bloco DO não basta para identificar o comando que gerou o erro e que escolher o primeiro de vários quadros SQL pode esconder origens divergentes. Torne a decisão conservadora por construção: um cursor de fora não confirma por si só a posição dentro de bloco; havendo quadros distintos ou comandos internos não verificáveis, produza a evidência parcial a partir do último arquivo alcançado. Exija uma origem exata só quando houver um único comando e os sinais presentes convergirem. Mantenha a prova de migrações normais, o caso de origem exata demonstrável e as asserções de origem parcial em situações ambíguas. Não amplie o reconhecimento para novas linguagens ou formatos.
