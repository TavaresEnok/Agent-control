# Escopo dos pedidos de correção dos módulos

Implemente a granularidade prevista na seção Como todo módulo funciona. Uma seleção com múltiplos arquivos deve criar pedidos normais separados por arquivo. Para atualizações de dependências, cada atualização vira um pedido, inclusive quando várias ficam no mesmo manifesto. Preserve pedido único para múltiplos achados do mesmo arquivo nos demais módulos. Toda seleção é atômica num único bloqueio e transação, sem despacho parcial caso algum ID seja inválido, não confirmado, protegido ou de outro projeto. Preserve a prevenção de links simbólicos, tratamento especial comprovado de prontidão e garantia de somente teste no caso protegido. Mantenha estáveis os identificadores para repetições, concorrência e sobreposição de seleções. Recupere pedidos agregados legados com o mesmo conjunto sem duplicá-los nem ampliar autoridade em uma nova seleção. Ajuste CLI/API/painel quando necessário: preserve formato e comportamento existentes para um único pedido, exponha todos os IDs quando múltiplos. Cubra API e PostgreSQL com arquivos e atualizações distintos, rejeição atômica, idempotência e legado. Trabalhe na criação de pedidos e sua apresentação; não reimplemente a reverificação.
